# 01 需求：用户、目标、范围和成功标准

题号：**3 · 企业知识问答 Agent**

## 用户与场景

- **用户**：公司员工，想查制度（报销、休假、差旅、IT 安全、加班）或产品 FAQ（云笺笔记）里的规定。
- **痛点**：制度分散在多份文档里，版本不同、措辞不同，甚至互相矛盾。员工要的是"能拿去执行的答案"，答错比答不上更糟，比如按 15 天报销结果其实适用 30 天，或者反过来。
- **目标**：给出有原文依据的回答；资料冲突、缺失或工具故障时，明确说出来，而不是编一个答案。

## 输入

| 输入 | 说明 |
|---|---|
| 问题 | 自然语言，必填 |
| 对话历史 | 可选，`[{"role": "user" \| "assistant", "content": ...}]`，用于追问和用户确认 |
| 知识库 | `data/docs/*.md`，每份带 `doc_id`、标题、`version_date`、发布部门，正文按段落切分 |

## 输出（每轮）

| 字段 | 说明 |
|---|---|
| `status` | `answered` / `conflict_needs_confirmation` / `need_clarification` / `insufficient_evidence` / `tool_error`（以上由模型选择），以及 `incomplete`（达到步数上限）/ `llm_error`（模型调用失败）（以上由程序给出） |
| `answer` | 回答；冲突时写清各文档的规定；无法回答时说明原因 |
| `citations` | `doc_id`、标题、版本日期、逐字原文片段 |
| `gaps` | 资料缺口或未确认事项 |
| `clarification_question` | 需要用户确认或补充的问题 |
| `trace` | 每一步的动作、参数、决策依据（模型给出的 `reason`）、返回摘要、后续动作 |

## 范围

**做**：
- 模型驱动的循环：模型选择检索、读取原文、改写查询或结束 → 程序执行工具 → 模型观察结果后决定下一步。
- 两个业务工具：`search_docs`（文档检索）和 `read_doc`（读取原文）。
- 由程序强制执行的校验：引用必须是本轮读过的原文；结束状态要满足对应条件；步数和工具调用次数有上限。
- 故障注入，用来模拟工具失败。
- 真实模型（OpenAI 兼容接口，如 DeepSeek、通义千问）和离线 Mock 两种运行方式。
- CLI：`ask`（单问）、`chat`（多轮）、`run-cases`（批量验收）。

**不做**：界面、线上部署、向量检索、多 Agent、权限控制、真实公司数据。

## 成功标准

题目要求的验收点，以及考核规则额外要求的步数上限和替换文档，都对应到 `examples/cases.json` 里的用例：

| 验收点 | 用例 | 期望行为 |
|---|---|---|
| 明确答案 | C01、C11 | `answered`，引用 D03 / D01，答案含 5 天 / 30 天 |
| 文档冲突 | C03、C04、C12、C13、C14 | D01 写 30 天、D02 写 15 天且未写优先级时返回 `conflict_needs_confirmation`，同时引用两份文档，并在追问中列出可选的制度，**不得擅自回答 15 天**。反例也要处理对：原文写明适用范围（C12）时按范围分别回答；同一文档内的分档数值不是冲突（C13）；新版本写明替代旧版本时采用新版本（C14） |
| 资料外问题 | C06 | `insufficient_evidence`，`gaps` 非空，不凭常识作答 |
| 改写后的相似问题 | C02、C07 | C02 与 C01 同义，答案和引用一致；C07 用"WFH"，需要模型把查询改写成"远程办公"再检索 |
| 上下文追问 | C04、C05 | 结合历史理解"那……呢"；用户确认适用制度后按该制度回答 |
| 工具失败 | C08、C09 | 临时故障由模型决定是否重试，重试后完成；持续故障返回 `tool_error`，没有引用，也不编造 |
| 信息不足需追问 | C15 | "这个能报销吗？"没有可指代的对象，返回 `need_clarification` 并追问 |
| 步数上限（考核规则） | C10 | 步数上限设为 2 时返回 `incomplete` / `step_limit_reached` |
| 替换文档（审核要点） | C11、C12、C14、`tests/test_cases_offline.py` | 修改、移除或新增文档后，答案和动作随之改变 |
| 稳定性（v2 新增） | 全部用例 × 3 次 | 每个用例独立运行 3 次，统计通过次数 |

**关键缺陷红线**：无依据的回答、引用不支持答案、文档冲突时擅自选一个答案。这三条都由程序在 `finish` 时校验（见 [02-solution.md](02-solution.md#程序强制的校验)），不只靠提示词约束。
